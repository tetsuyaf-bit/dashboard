# 社内Webダッシュボード 要件定義書

## 1. プロジェクト概要

### 1.1 プロジェクト名
社内情報共有Webダッシュボードシステム

### 1.2 目的
社内の各部門の状況を可視化し、情報共有を円滑にするためのWebダッシュボードを構築する。

### 1.3 背景
- 各部門の状況が把握しづらい
- 重要な情報共有が遅れがち
- 社内全体の健康状態を一目で確認できる仕組みが必要

### 1.4 対象ユーザー
全社員（想定ユーザー数：XX名）

### 1.5 開発規模
小規模開発

---

## 2. システム要件

### 2.1 機能要件

#### 2.1.1 コンディションランプ機能

**概要**  
各部門・領域の状況を赤・黄・青の3段階で可視化する機能

**対象領域（初期設定例）**
- セールス
- サービス
- プレゼンテーションコンテンツ
- 社内環境
- PR
- プロダクト
- キャッシュ

**領域の管理**
- スプレッドシートに新しい行を追加することで領域を追加可能
- 行を削除することで領域を削除可能
- 領域名は自由に変更可能
- ダッシュボードはスプレッドシートの内容に応じて動的に表示を変更

**機能詳細**
- 各領域のステータスを色で表示（赤：注意、黄：要注意、青：良好）
- ステータスはスプレッドシートを直接編集して更新（編集権限を持つユーザーのみ）
- 各ステータスにコメント（理由・詳細）を付与できる
- ステータス更新日時と更新者を表示
- ダッシュボードのトップページに全領域のランプを一覧表示
- 各ランプをクリックすると詳細情報（コメント、履歴など）を表示
- データはスプレッドシートから定期的に取得して表示を更新
- スプレッドシートで追加・削除された領域は自動的にダッシュボードに反映

#### 2.1.2 掲示板機能

**概要**  
社内の重要なお知らせや情報を共有するための掲示板

**機能詳細**
- スプレッドシートに新しい行を追加することで投稿を作成
- 投稿の編集・削除はスプレッドシートで該当行を編集・削除
- タイトル、本文、投稿日時、投稿者を表示
- カテゴリー分類（お知らせ、イベント、システム連絡など）
- 重要度フラグ（通常、重要）の設定
- 新着順、重要度順での並び替え（ダッシュボード側で実装）
- 添付ファイルはGoogle Driveにアップロードし、URLをスプレッドシートに記載
- データはスプレッドシートから定期的に取得して表示を更新

### 2.2 非機能要件

#### 2.2.1 パフォーマンス
- ページ読み込み時間：3秒以内
- 同時アクセス：XX名まで対応
- スプレッドシートからのデータ取得：リアルタイムまたは数分間隔のキャッシュ

#### 2.2.2 セキュリティ・権限管理
- Google Workspace アカウントによる認証
- スプレッドシートの共有設定による権限管理
  - 閲覧権限：全社員（ダッシュボード表示用）
  - 編集権限：管理者のみ（コンディションランプ・掲示板の更新）
- スプレッドシートへの直接アクセスは編集権限者のみ
- ダッシュボードは社内のGoogle Workspaceアカウントのみアクセス可能

#### 2.2.3 ユーザビリティ
- レスポンシブデザイン対応（PC、タブレット、スマートフォン）
- 直感的なUI/UX
- アクセシビリティに配慮

#### 2.2.4 可用性
- Google インフラの可用性に依存
- スプレッドシートのバックアップは定期的に実施

## 3. 画面構成

### 3.1 画面一覧

1. **ダッシュボード（トップページ）**
   - コンディションランプ一覧表示（スプレッドシートから取得）
   - 掲示板の最新投稿（上位5件程度、スプレッドシートから取得）
   - Google認証によるログイン状態の表示

2. **コンディションランプ詳細画面**
   - 選択した領域の詳細情報
   - 現在のステータスとコメント
   - 更新日時と更新者

3. **掲示板一覧画面**
   - 投稿一覧（スプレッドシートから取得）
   - カテゴリー・重要度によるフィルタ機能

4. **掲示板投稿詳細画面**
   - 投稿の詳細表示
   - 添付ファイルのリンク（Google Drive）

5. **データ編集**
   - スプレッドシートを直接開いて編集（管理者のみ）
   - ダッシュボードから「スプレッドシートを開く」リンクを提供

---

## 4. ユーザー権限

### 4.1 権限管理方式
Google Workspace（Google スプレッドシート）の共有設定を利用した権限管理

### 4.2 一般ユーザー（閲覧のみ）
- ダッシュボードの閲覧
- コンディションランプの閲覧
- 掲示板の閲覧
- スプレッドシートへは閲覧権限のみ付与

### 4.3 管理者（編集権限）
- 一般ユーザーの権限に加えて以下が可能
- コンディションランプの編集（スプレッドシートを直接編集）
- 掲示板投稿の作成、編集、削除（スプレッドシートを直接編集）
- スプレッドシートへは編集権限を付与

### 4.4 権限付与方法
- Google Workspace管理者またはスプレッドシート所有者が、スプレッドシートの共有設定から権限を付与
- 特定のGoogleアカウントまたはグループ単位で権限設定可能

## 5. データ要件

### 5.1 データ管理方式
Google スプレッドシートを使用したデータ管理

### 5.2 スプレッドシート構成

#### シート1：コンディションランプ
| 列名 | データ型 | 説明 |
|------|---------|------|
| 領域名 | テキスト | 任意の領域名（自由に追加・削除可能） |
| ステータス | テキスト | 赤/黄/青 |
| コメント | テキスト | ステータスの理由や詳細 |
| 更新日時 | 日時 | 最終更新日時 |
| 更新者 | テキスト | 更新したユーザーのメールアドレスまたは氏名 |

**注意事項**
- 行の追加・削除により領域を自由に増減可能
- ダッシュボードは行数に応じて動的に表示を変更
- 領域の並び順はスプレッドシートの行順に従う

#### シート2：掲示板投稿
| 列名 | データ型 | 説明 |
|------|---------|------|
| 投稿ID | 数値 | 自動採番 |
| タイトル | テキスト | 投稿タイトル |
| 本文 | テキスト | 投稿内容 |
| カテゴリー | テキスト | お知らせ、イベント、システム連絡など |
| 重要度 | テキスト | 通常/重要 |
| 投稿日時 | 日時 | 投稿日時 |
| 投稿者 | テキスト | 投稿者のメールアドレスまたは氏名 |
| 添付ファイルURL | テキスト | Google Driveリンク（任意） |

#### シート3：ユーザー管理（任意）
| 列名 | データ型 | 説明 |
|------|---------|------|
| メールアドレス | テキスト | Googleアカウント |
| 氏名 | テキスト | ユーザー名 |
| 権限 | テキスト | 一般/管理者 |

### 5.3 データ更新方法
- 管理者がスプレッドシートを直接編集することでデータを更新
- ダッシュボードは定期的にスプレッドシートからデータを取得して表示を更新
- データ取得方法：Google Apps Script API、またはGoogle Sheets API

## 6. 技術要件

### 6.1 採用技術スタック

**データベース**
- Google スプレッドシート または AppSheet
- データの管理・更新はスプレッドシートで実施

**フロントエンド**
- HTML5, CSS3, JavaScript
- フレームワーク：React, Vue.js など
- Google Apps Script（スプレッドシート連携用）

**バックエンド**
- Google Apps Script（スプレッドシートとの連携API）
- または、スプレッドシートをデータソースとして直接読み込み

**認証・権限管理**
- Google Workspace のアカウントと権限を使用
- スプレッドシートの共有設定で閲覧・編集権限を管理

**ホスティング**
- Google Apps Script Web アプリ、またはGitHub Pages等の静的サイトホスティング

### 6.2 ブラウザ対応
- Google Chrome（最新版）のみ対応
- その他のブラウザは動作保証外
